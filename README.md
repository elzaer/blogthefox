# HowTheFox — musings

A tiny, no-framework blog. You write plain Markdown files, run one script,
and it spits out plain HTML you can upload anywhere. No CMS, no database,
no server-side code, no JavaScript build step. Just files.

## What's in here

```
howthefox-musings/
  posts/            <- you write here (one .md file per post)
  templates/         <- the two HTML shells (post page, index page)
  static/            <- stylesheet + the fox icon
  config.py           <- your site name, domain, and section path
  build.py             <- the script that generates the site
  musings/           <- OUTPUT, generated by build.py — don't hand-edit
```

Only `posts/`, `config.py`, `templates/`, and `static/` are meant to be
edited by hand. Everything in `musings/` is regenerated from scratch every
time you run the build, so don't bother editing it directly.

## Writing a new post

1. Add a file to `posts/` named `YYYY-MM-DD-a-short-slug.md` — the date
   becomes the post date, and the slug becomes the URL
   (`/musings/a-short-slug/`).
2. Make the first line of the file a level-1 heading — that's your title:

   ```
   # A short thing I noticed today

   Whatever you want to say. Plain Markdown: paragraphs, *italics*,
   **bold**, [links](https://example.com), > blockquotes, lists, all of it.
   ```

3. (Optional) Add a one-line summary at the top for nicer previews and
   social-share text. If you skip this, one is auto-generated from your
   first paragraph.

   ```
   ---
   summary: One sentence describing the post.
   ---
   # A short thing I noticed today

   ...
   ```

4. Run the build:

   ```
   python3 build.py
   ```

That's the whole workflow. No accounts, no drafts folder in some app,
no "publish" button — the file *is* the post.

To pull a post down without deleting it, rename the file to start with an
underscore (e.g. `_2026-09-17-not-ready-yet.md`) and it'll be skipped by
the build.

## Previewing locally

From the project root (the folder *above* `musings/`, so that `/musings/...`
resolves the same way it will on the real site):

```
python3 -m http.server 8000
```

Then open `http://localhost:8000/musings/` in a browser.

## Deploying

Upload the contents of the `musings/` folder to your web host so that it's
reachable at `https://howthefox.com/musings/` (or wherever you've set
`SECTION_PATH` in `config.py` — see below). That's it: it's static files,
so any host that can serve HTML works — the same place the rest of
HowTheFox.com already lives, an S3 bucket, Netlify, GitHub Pages,
whatever you're using.

Re-run `python3 build.py` and re-upload the `musings/` folder any time you
add, edit, or remove a post.

## Configuration

Everything site-wide lives in `config.py`:

- `SITE_NAME` — shown in the header and page titles
- `SITE_URL` — your domain, e.g. `https://howthefox.com`
- `SECTION_PATH` — where this section is mounted, e.g. `/musings`.
  Change this if you'd rather it live at `/writing` or `/notes` or
  wherever — nothing else needs to change.
- `AUTHOR` — used in the meta description and RSS feed

## Social sharing

Every post page carries its own Open Graph and Twitter Card meta tags
(title, description, canonical URL), so when someone pastes a link on
social media, they'll get a proper title/description card rather than a
bare URL — no extra work needed per post.

## RSS

A `feed.xml` is generated alongside the site, so anyone (or any feed
reader / auto-poster) can subscribe at `/musings/feed.xml`. Delete the
`write_feed(...)` call near the bottom of `build.py` if you'd rather not
generate one.

## Extending it later

If you eventually want tags, pagination, or a different look, it's all in
two template files (`templates/post.html`, `templates/index.html`) and one
stylesheet (`static/style.css`) — no framework to fight with. `build.py`
is about 150 lines of plain Python and is meant to be readable end to end.
